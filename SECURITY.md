# Security Policy

At **DIVMORA Technologies**, security is fundamental to everything we engineer. We take vulnerability reports seriously and appreciate responsible disclosure from the security community.

---

## Supported Versions

Only the latest active minor release receives security updates and vulnerability patches:

| Version | Supported          |
| :------ | :----------------- |
| `0.1.x` | :white_check_mark: |
| `< 0.1` | :x:                |

---

## Reporting a Vulnerability

If you discover a potential vulnerability or security flaw in **`license-go`**, please do **NOT** open a public issue.

Instead, please report the vulnerability through one of the following secure channels:

1. **GitHub Private Security Advisory**: Submit an advisory via the repository's **Security > Advisories** tab on GitHub.
2. **Email**: Send detailed findings to **[security@divmora.com](mailto:security@divmora.com)**.

### Information to Include:
- A description of the vulnerability and its potential security impact.
- Clear step-by-step instructions or proof-of-concept (PoC) code to reproduce the issue.
- Any suggested mitigations or patches, if available.

---

## Response SLA

- **Initial Acknowledgment**: Within **48 hours** of report receipt.
- **Triage & Verification**: Within **5 business days**.
- **Fix & Disclosure**: We will collaborate with you to develop a patch and coordinate public disclosure once the fix is released.
